## Feedback items

### R1 — Quit waits for startup before it can cancel startup

- Source: https://github.com/narumiruna/pi-remote/pull/7#discussion_r4303236718
- Scope: in scope. The PR adds the unconditional startup wait to ordinary Quit.
- Severity: P2. A blocked version check can delay Quit until the utility deadline, even when no Pi work needs consent.
- Evidence: `requestTermination` awaits `startup.value` before host consent checks. `shutdown` cancels startup only after that wait. `startNetwork` awaits `HostCoordinator.inspectPi`; `LocalCommand.run` has a 15-second deadline and supports cancellation with bounded child cleanup.
- Outcome: Already addressed in published fix `5606abc`.
- Fix: removed the wait before authoritative host consent. After consent is accepted and admission is closed, existing shutdown cancels startup before awaiting it. Cancel does not cancel startup or change work.
- Evidence: the new blocked `--version` fixture failed its four-second reply check on the original code. It passes after the fix for normal and TERM-ignoring children, including child exit and no listener start. The Cancel test verifies that network startup can finish while local Pi work remains active. Existing stale-consent and duplicate-reply tests pass.
- Reply: https://github.com/narumiruna/pi-remote/pull/7#discussion_r4303367923.
- Thread: resolved through `resolveReviewThread`; the API returned `isResolved: true` after the fix was pushed.

### R4 — Mutating storage failure can lose Quit protection

- Source: https://github.com/narumiruna/pi-remote/pull/7#discussion_r4303385941
- Scope: in scope. The PR adds host-side tracking for unresolved Quit outcomes but does not include every uncertain result used by `SubmissionState`.
- Severity: P2. Quit can omit consent after a mutation succeeds in Pi but local session persistence fails.
- Evidence: `SubmissionState.finish` treats `.unknownOutcome` and `.storageFailure` as uncertain. The host catches `.storageFailure` after an admitted rename, but only `.unknownOutcome` sets `unresolvedQuitOutcome`. The pending set then clears while the session is idle. `rename` can complete `set_session_name` before `adoptSessionName` fails to save `sessions.json`.
- Outcome: Actionable and not yet addressed; implementation and validation pass, publication is pending.
- Fix: retain `.storageFailure` from admitted state-changing actions in the existing unresolved-outcome flag. The `request.action.mutates` guard still excludes unrelated read errors. Explicit successful Stop/lifecycle recovery and consent validation are unchanged.
- Evidence: a test replaces only the private fixture's session-catalog file with a directory. Pi accepts Rename and returns the new name, but the host cannot save the catalog. The original code returns an idle token with `requiresConfirmation: false` in all three test cases. After the fix, consent remains required after an unrelated read error, unconfirmed shutdown is rejected, and confirmed Quit or successful Stop/Close recovery is allowed.
- Thread: open until validation passes and the fix is published.
