# Mac interface and folder-path verification

## Current Pi-like interface

The Mac coding surface now follows the supplied terminal references: a persistent Pi startup/resource header, a compact growing ruled editor and a two-line footer in one native scroll flow. Standard extension widgets keep their above/below-editor positions and status entries use the footer. Informational notices start collapsed; warnings/errors remain visible. Custom TUI factories are not transported by RPC. The workspace sidebar starts hidden; the inspector and management features remain accessible. Enter submits, modified Enter adds a newline, and Return/Tab with suggestions completes only. Reviewed `!`/`!!` shell execution and local queued-input recovery use typed upstream RPC actions. See [current behavior, verification and remaining acceptance](pi-like-mac-verification.md) and the [terminal reference](pi-like-mac-reference.md).

The sections below record earlier workspace-first behavior and verification. Their white surfaces, persistent-sidebar default, session-header layout and Return/Command-Return editor map are superseded by the Pi-like Mac change. They remain historical evidence, not proof of current normal-launch behavior.

## Earlier implemented behavior

The Mac app uses a persistent workspace/session sidebar, a conversation area and an optional Files/Session/Activity inspector. The native split panes resize independently; the conversation stays wider than either secondary pane. The minimum window is 900 × 600 points. White surfaces, native controls and the existing blue accent remain; there is no theme setting.

Use **Workspaces + → Add workspace** to browse, enter a path or use the native folder chooser. Adding a workspace does not start Pi. Select the workspace, then use the toolbar's **New session** action or the workspace context menu. There is no standalone New session row under each workspace. Import is in **Workspaces +**; Devices and Settings remain pinned below the scrolling workspace list. With no workspace selected, New session offers a directory picker and recent workspaces. Expand a workspace to select a saved session. Full canonical paths identify groups; identical final directory names do not merge unrelated folders. Confirmed Remove workspace hides only the sidebar entry, not files, saved sessions or active work. Re-adding the directory reveals its sessions again.

The toolbar has one compact **iPhone access** summary; off means remote connections are disabled, not that local Pi is unavailable. Select it to read listener state, authenticated device connections and the secure endpoint, or to open Settings/Devices. The displayed session header shows Pi execution; other destinations keep active-session status in the global header. Pi version is available in Settings and session controls, not the global header. Local work requires neither listener nor pairing. **Settings** contains network, Pi executable, folder-access and Advanced identity-replacement controls. **Devices** contains pairing, live authenticated connection status and confirmed revocation. Pairing alone does not indicate a live connection. Stopping the listener disconnects phones without stopping Pi.

The backend supports one active Pi child. UI selection is separate from the loaded session. Selecting another saved session while Pi works shows that session's metadata and explains why activation is unavailable; it never shows the active session's messages under another title or stops work implicitly. When idle, opening a session restores its saved conversation through the existing lifecycle APIs, without replaying prompts. An exited session retains displayed output and offers explicit Open session recovery. The composer is disabled when execution is unavailable.

The inspector reuses the paged directory browser, session controls and tool transcript. Files is the single Mac file-browser destination; the composer shortcut opens that inspector without replacing Chat. There are no Conversation/History tabs. Use `/history` or `/tree` in the composer, or the session overflow menu. Files supports directory navigation, relative-path copying and validated Finder reveal. A dedicated Commands sheet opens directly from the composer and shares command arguments, dispatch and error handling with session controls. Session retains model, thinking, usage, runtime settings, export and lifecycle controls. History retains fork/clone inspection. Activity displays actual tool results/errors and notices, not invented durations. Session context menus expose Open, ID copy and loaded-session controls/history actions. The loaded, idle session also has a direct **Rename** sheet using the existing scoped Pi rename action. Saved sessions must be opened before renaming; no local alias store is added. No session deletion action is added because its semantics are not defined.

Workspace visibility, expansion, selected metadata and inspector visibility use existing local preferences. Sidebar/inspector widths and sidebar visibility use scene storage. Unsent drafts are saved per session with a 400 ms debounce and shutdown flush, limited to 256 KiB each and 8 MiB total; an oversized draft stays in memory with a copy-before-close warning. No credentials enter these stores. Restored UI selection does not automatically start Pi. Command-N creates a session; Command-Option-S and Command-Option-I toggle the sidebar and inspector.

Mac sheets have a bounded viewport based on the parent window, with a visible Close action outside the scrolling content. Grouped forms scroll instead of expanding the sheet to the full intrinsic content height. This fixes the session-controls overflow shown in the reported screenshot.

## Mac session management

Close Session is a non-destructive Mac workflow. Use the row close button, context menu, header actions, Session inspector or Command-Shift-W for the selected session. It removes that session from the sidebar, not its workspace, and keeps saved history and drafts. Hidden row buttons do not accept pointer input; keyboard focus reveals them. The toolbar also provides Switch session (Command-Shift-O) and Command palette (Command-Shift-P). Command-W retains its native window behavior.

An unloaded saved session needs no RPC action. A loaded idle session uses the existing scoped `.closeSession` action. For a working session, the host issues an opaque local token before the confirmation dialog opens. It binds consent to host, epoch, session, process lifecycle and work generation. The host validates it before a new Stop dispatch; later work, pending dialogs or pending mutations require a new decision. Ordinary streaming output does not invalidate the token. The token has no public initializer or wire encoding. Existing request replays return their recorded result or unknown outcome without another Stop. Stop and Close clears queued work, sends scoped Stop, waits at most five seconds for the same runtime to report idle after Stop returns, then sends scoped Close. The existing bounded RPC/shutdown waits still apply. File changes cannot be undone. Pending dialogs/actions, uncertain outcomes and unsafe lifecycle phases reject close. Identity and pending-state guards run after suspension; a failed, cancelled or uncertain close leaves the sidebar entry available.

Before closing the loaded session, the model flushes the latest bounded draft. An oversized draft blocks close with a copy-before-close warning. Closed IDs use a separate local version-1 preference, bounded to 10,000 IDs and 1 MiB. Corrupt, wrong-type or unknown-version records are not overwritten; a warning explains that in-memory visibility will not be saved. Existing workspace preferences, catalog and Pi JSONL formats are unchanged. Before hiding a loaded session, compare the post-close snapshot sequence with the latest observed state. A newer same-ID activation rejects the visibility change. A later authoritative activation removes the closed ID and reveals its workspace. In-memory receipt watermarks prevent delayed pre-close snapshots from being mistaken for a new activation.

`/resume` and Switch session search the full managed catalog by display name, workspace/path, status or stable ID, including closed sessions. Search and arrow navigation do not activate Pi; Return or a result/Open button does so explicitly. Failed activation leaves the closed entry closed and keeps the picker available. Successful activation reveals the session and its workspace and restores the existing per-session draft. A workspace with only closed sessions offers Switch session rather than directing the user to empty sidebar rows.

Overview groups saved sessions by workspace and distinguishes loaded phase, pending input, errors, unloaded history, interrupted history and closed sessions. View conversation remains available for the loaded session during work and changes only UI selection. Other sessions cannot interrupt the active runtime. The native action palette searches only implemented app/native navigation actions, including Add workspace, Settings, Devices and Rename session. Palette Rename requires the displayed, loaded idle session and rejects a changed session context; disabled actions show a reason. It reuses slash-workflow availability and dispatch without replacing the draft or forwarding commands to Pi. Native search fields support arrow selection, Return and Escape without intercepting marked-text confirmation. Dismissing a picker restores the prior responder when it still exists.

Concurrency and split conversations are not implemented. The [runtime design](mac-session-runtime-design.md) records the one-writer ownership and per-device replay proposal. Changing shared Mac/iPhone runtime selection requires the explicit compatibility decision retained in the open implementation plan.

### Mac review follow-up

Ordinary Quit, including native application Quit and menu-bar Quit, uses one termination decision. Active, waiting or uncertain work and pending mutations require Cancel or Stop work and quit. The alert explains that phones disconnect, managed Pi stops and file changes cannot be undone. Cancel has initial focus and Escape; the destructive button has no default key equivalent. An existing extension sheet does not delay the confirmation behind that sheet. OS-forced termination is outside this guarantee.

The coordinator issues a local-only token bound to host/epoch/session, process and work generations, accepted-mutation revision, pending requests, dialog IDs and lifecycle transition. Consent is rechecked before the coordinator closes action admission in the same actor turn. New work requires a new decision; ordinary message completion does not invalidate consent. If work finishes while confirming, idle shutdown needs no second confirmation. Repeated Quit requests share one decision and one termination reply. Shutdown still uses the existing bounded child cleanup and does not resend instructions.

The Mac Session inspector closes through the existing guarded sidebar/header workflow, including token validation, draft flushing and visibility changes only after success. Its close control stays pinned below idle-only session settings. Closing to a workspace keeps the split panes at full viewport height and empty inspector tabs at the top. The redundant visible Inspector label is hidden to keep Files/Session/Activity on one row. The iPhone retains its Close Pi session path. Palette actions reuse existing routes and recheck availability at dispatch; navigation does not execute Pi commands or replace drafts.

## Mac usability refinement verification

The Mac refinement keeps the existing architecture and light appearance:

- Session rows and the header use display labels, not rewritten persisted names. Priority is a non-default stored name, a confirmed Pi JSONL name, the first meaningful textual user instruction, then a stable session ID. An explicit Pi name equal to the workspace basename is retained when confirmed by metadata. Blank/image-only messages do not become labels. Labels are bounded to 70 characters, with stable suffixes for all same-workspace collisions, including collisions with generated labels. Middle truncation keeps distinguishing suffixes visible; tooltips expose the longer label, path and session ID.
- A local-only host API reads coordinator-owned JSONL files without activating Pi. It opens every path component with no-follow descriptors and validates the managed session header on the same descriptor used for parsing and cache lookup. A scan reads at most 2 MiB; a cache hit rereads at most 64 KiB for header validation. Metadata strings are bounded to 4,096 UTF-8 bytes. The identity/size/mtime cache retains at most 256 entries; five-minute expiry is checked on metadata reads. A partial scan can supply a first instruction but never a confirmed latest name. Missing, invalid, inaccessible or symlink-redirected files use the stable fallback. Names and prompt previews are not routine diagnostics or new persisted fields.
- UI reads are asynchronous and publish per-session results. Unchanged reads continue when another session changes. A cached, workspace-scoped label map avoids repeated whole-catalog scans for each row. The complete live transcript can provide an instruction before the first file update; a bounded transcript with older messages cannot claim its first visible message is the session's first instruction.
- The toolbar has one prominent New session action. Workspace menus provide contextual creation, Add workspace and Import. Devices/Settings use a separate pinned native list. Session selection/expansion, busy activation rejection and draft persistence remain.
- At this earlier checkpoint, the compact header showed the session title, workspace/model/thinking metadata, actual Pi lifecycle status and Conversation/History tabs without a visible Session view label. The slash-command change above removes those tabs. The overflow menu contains controls, Rename, Commands, Files, diagnostics and path copy. The full working directory remains in tooltips and session controls.
- Mac messages use a bounded readable width and 15-point system text. Tool results, thinking, Markdown, code, images, errors and copy remain available. The composer is a native multiline TextEditor with a 76–180-point viewport, a subtle border and labelled Files/Commands/Stop/Send controls. Return inserts a newline; Command-Return sends. Empty/whitespace, unavailable and pending Send are disabled. Steering/follow-up remains explicit while working. There is no nonfunctional Attach control; Files retains preview-based text attachment.
- Extension notices move to Activity. They are not removed, and faults/dialogs remain visible through their existing recovery and request paths. Opening, unavailable and load-failure views retain next actions without claiming readiness. Empty workspaces direct the user to New session in the toolbar.

## Manual Mac folder paths

The directory picker supports typed or pasted paths when the host advertises `directory-path`:

1. On Mac, select **Edit path**. On iPhone, the path field is already visible.
2. Enter an absolute Mac path, `~` or `~/folder` and select **Go** to open the folder.
3. Review its resolved canonical path and select **Start Pi Here**.

Mac Files uses a compact resolved-folder breadcrumb with ancestor navigation, a parent action and **Copy full path**. **Full canonical path** expands selectable path text. Folder-selection sheets always show the resolved canonical path for review; long paths scroll horizontally within a bounded row. Mac controls use native sizes; iPhone controls retain their 44-point minimum touch targets.

Go never creates a folder, launches Pi or sends a prompt. Editing a path disables session selection until that path is opened. Invalid or pending navigation clears the old selectable folder. Retry uses the exact attempted path, and stale or cancelled responses cannot replace newer navigation.

The authenticated `directoryAtPath` action returns the existing bounded directory page and opaque directory ID. Session launch still uses that ID and revalidates its filesystem identity and permissions. The Mac expands only its own home prefix; it does not invoke a shell or expand environment variables, relative paths, `~otheruser` or shell expressions. Literal spaces and shell punctuation in valid filenames remain literal. Paths over 4,096 UTF-8 bytes or containing NUL are rejected. Existing read/search permissions and symbolic-link handling remain in force. Folder selection is not a tools sandbox.
