# Pi Remote

Native Swift apps to control [Pi](https://github.com/earendil-works/pi) directly on your Mac or from an iPhone, without an embedded terminal. The macOS app is **Pi Remote for Mac**.

Choose a Mac directory from your phone, start a managed session, watch output and tool activity, send instructions, and stop work. Pi, files, tools and provider credentials stay on the Mac. Pi still sends model requests to its configured provider; this is not an offline AI system.

## UI terms

Both apps use Pi's terms: **Prompt**, **Steering**, **Follow-up**, **Thinking level**, **Steering mode**, **Follow-up mode**, **Last assistant message** and **Pi changelog**. Steering waits for the current response and tool calls to finish; follow-up waits until Pi finishes the current task. **Workspaces**, **Connections** and **Devices** are app-specific controls. System and compaction instructions keep the term **instructions**.

## Security and network limits

- A paired phone is a trusted Pi controller. Pi can change files and run commands with the Mac user's permissions. Folder selection is not a tools sandbox.
- Pairing requires a short-lived code scanned or copied from the Mac and explicit approval on the Mac. TLS checks the pinned certificate, hostname and validity. Each connection requires device authentication.
- Credentials use Keychain. The phone requires Face ID or its device passcode before access after launch or background return. Hardware behavior remains unverified.
- The listener binds one selected private IPv4, loopback or Tailscale IPv4 address. No public listener, router port forwarding, hosted relay or account service is included.
- LAN and off-site Tailscale are required for the first personal build. Authenticated local LAN and Tailscale tests pass, including a simulator coding flow. Only the older diagnostic has passed a physical LAN test; off-site access remains unverified.
- The companion owns separate Pi session files. It cannot attach to an existing terminal Pi session. Do not open its managed files for writing in another Pi process.
- Companion exit stops its child. Ordinary Quit asks for confirmation before interrupting active, waiting or uncertain work; Cancel leaves work running. Changed work requires fresh consent. Forced termination cannot guarantee a confirmation. A sleeping Mac is unavailable. Interrupted work is not automatically repeated; inspect uncertain outcomes before retrying.
- Routine diagnostics exclude credentials, pairing codes, prompts and tool output. Output and history views have explicit size limits; see [limits and recovery](docs/native-apps.md#resource-and-recovery-limits).

## Local development setup

Pi **1.3.0** is the tested development runtime. Other Pi versions are unverified. Complete upstream Pi core RPC coverage is still unverified; this is not a supported release.

1. Install and configure Pi on the Mac before using the companion. Provider credentials stay in Pi's Mac configuration. Check `pi --version` and use a status-only authentication check for your provider. This laptop passes `pi auth check --provider openai-codex --model gpt-6.1-sol --json --no-refresh`. Do not use credential-printing commands or copy keys to the phone.
2. Generate and build the apps with the [verified commands](docs/native-apps.md#automated-checks). Launching a signed personal build is separate and remains unverified. The simulator checks below use injected authentication results and memory credentials, not a production unlock bypass.
3. In **Pi Remote for Mac**, open **Settings → Pi and folder access → Choose Pi executable** if the detected path is wrong. The companion finds Node.js in the Pi executable directory, Homebrew locations, its inherited `PATH` and installed fnm default aliases. It does not run shell startup files or install a runtime. For local use, select **New session** and choose or enter a Mac folder. To manage saved groups, open **Sidebar → Workspaces + → Add workspace**. Expand a workspace to preview its saved sessions, then use Open explicitly. The workspace context menu also creates sessions; Import is in **Workspaces +**. The loaded, idle session supports `/name` and **Rename** in its sidebar context menu. Starting the server and pairing a phone are not required. Only one Pi session executes at a time; selecting another saved session never stops active work.
4. For iPhone access only, select a private LAN or Tailscale **Listen address** under **Settings → iPhone access (optional)**, then **Start iPhone access**. Use **Refresh addresses** while access is stopped after a network or Tailscale change; this keeps pairings and does not replace identity. The main window separates remote access from session execution. Select **Actions → iPhone access** for listener status, authenticated device connections and, when listening, the secure address and port. iPhone access being off does not prevent local Pi work. Port 7443 must be reachable. Keep the Mac awake. For Tailscale, both peers must be connected and access policy must allow the connection. Local checks do not prove off-site operation.
5. On the Mac, open **Settings → iPhone access (optional) → Devices** and select **Pair iPhone**. On the unlocked phone, open **Connections → Pair a Mac**, scan or paste the code, review the Mac address and select **Request pairing**. Compare the displayed device identity and select **Allow** on the Mac. A request alone does not grant access. Keep the code private; it expires after two minutes.
6. Open **Sessions → New session**, browse the Mac folders or enter an absolute Mac path or `~/folder` and select **Go**. Review the resolved path, then select **Start Pi Here**. Go only opens the folder; it does not start Pi. An edited path must be opened before session creation. No project registration is required. Use **Session controls** for the complete path, model, thinking level, commands, usage, last-response copy and runtime settings. Runtime changes require confirmation and can affect future Pi terminal sessions. **Close Pi session** keeps saved history and the listener. To add Mac text, open **Mac files**, read the file preview and select **Attach text**. This changes the draft only; review it before sending.
7. Send an instruction. While working, choose steering or follow-up explicitly before sending another instruction. **Stop** clears pending instructions and aborts work; it cannot undo file changes. Closing or locking the phone does not stop accepted work.
8. After a disconnection, unlock and reconnect to recover state. After a host restart, select the saved session explicitly. Review interrupted work before sending anything again. Unknown outcomes are not safe to resend automatically.

The companion catalog and managed sessions use `~/Library/Application Support/PiRemote/`. Do not open managed session files for writing in another Pi process. To remove access on the Mac, open **Settings → iPhone access (optional) → Devices**, expand the device, select **Revoke access** and confirm. Devices distinguishes saved pairing from an authenticated live connection. To change interfaces, stop the listener, select the new address and restart it; update the saved phone address without changing its certificate pin. If the certificate does not cover the new address, use **Settings → Advanced → Replace connection identity** and pair again. Do not disable TLS checks.

Clean setup evidence: two Mac-model tests pass with new private support storage and isolated preferences, including Start listener, local approval, persisted devices, listener restart and revocation. Thirty-one simulator tests pass with fresh phone preferences and a private local provider fixture, including product-model pairing, saved connections, nested directory selection and coding. These are local model/transport and simulator checks, not signed installation, hardware authentication, camera or off-site evidence. [Repeat the checks](docs/workflow-verification.md#clean-setup-controls).

## Mac session management

Use **Close Session** in a Desktop row context menu, the **Session** menu, the **Session** inspector or with Command-Shift-W. Pi mode also retains its sidebar hover Close control, including when the conversation alias selects the loaded row. This closes the chosen session, not its workspace, and keeps saved history and the draft. A working session requires **Stop and Close** confirmation; stopping cannot undo file changes. A failed or uncertain close does not hide the session. Stop and Close applies only to the work captured before the dialog; changed work requires a new confirmation. Reopen closed sessions explicitly through Overview's **Reopen**, `/resume` or **Switch session**. A later remote activation also restores that session to the sidebar.

**Actions → Overview** groups saved sessions by workspace and distinguishes loaded execution from saved or closed history. Closed sessions start collapsed; the loaded session remains in the normal group even if a saved closed preference is stale. Closed Overview rows offer Reopen, with no disabled Close control. Conversation and loaded-session aliases select the same sidebar row. **View conversation** returns to the loaded session while Pi works without starting or stopping a runtime. The **Session** menu groups switching, contextual actions and Close Session. From another destination, its inspector identifies the loaded session and offers **View active session**. **Actions** groups Overview, workspace actions, Settings and remote access. Devices is under Settings → iPhone access (optional); the palette retains a secondary direct Devices route. Files and Pi commands remain direct toolbar controls. See [structure corrections](docs/mac-interface-structure.md). Command-Shift-O opens the searchable session switcher. Command-Shift-P opens the native action palette. Search does not execute an action; choose a result explicitly. Return opens the selected search result, and Escape dismisses the picker. The palette preserves the message draft. It includes Add workspace, Settings, Devices and Rename session. Palette Rename requires the displayed, loaded idle session; unavailable actions explain what is needed. Desktop Session controls put Model and Thinking level first, with Details and Advanced initially collapsed. Desktop omits the Cycle buttons but keeps existing cycling actions and shortcuts. Pi version and Pi changelog are in Settings → Pi and folder access; Pi mode retains them and Cycle buttons in its legacy Session form.

These controls retain the current single-active-Pi limit. Independent concurrent runtimes and split conversations are proposed, not implemented; see the [runtime design and compatibility gate](docs/mac-session-runtime-design.md). Verification and remaining limits are recorded in [Mac interface checks](docs/mac-interface.md).

## Mac slash commands

- `/resume` opens saved companion-managed sessions. Opening the picker does not start or stop Pi; choose a session explicitly while idle. Terminal-owned Pi sessions are not listed.
- `/tree` opens authoritative session-tree inspection while Pi is idle. Forking remains a separate explicit action.
- `/history` opens paged saved history. The conversation remains the main view.
- Other entries come from Pi's discovered commands, skills and templates. Their existing RPC and busy-state restrictions remain. Completing a name only edits the draft; it does not execute a command.

Use Up/Down to select a suggestion, Return or Tab to complete, and Escape to dismiss. Press Enter again to submit. Native `/model`, `/thinking`, `/settings`, `/session`, `/new`, `/name`, `/compact`, `/fork`, `/clone`, `/copy`, `/export`, `/import`, `/changelog` and `/hotkeys` open their native controls; inline arguments are not supported for these controls. An accepted native command clears only its unchanged draft. A rejected command keeps the draft. Unsupported commands show an error and keep the draft. Slashes within ordinary text, nested absolute paths and existing root paths such as `/tmp` remain prompt text unless they match a registered command.

`@` and path completion insert paths only. Use **Files** in the toolbar to preview and attach file contents. Names with quotes, backslashes or control characters are omitted from completion. In Pi mode, startup, transcript, editor and footer retain one continuous placement. Desktop keeps the composer below an independent history viewport. Oversized extension/input content has scroll access within the dock. Pi mode leaves unused window space after the footer; this is not terminal scrollback. Reverse model cycling opens the selector because RPC only exposes forward cycling. Terminal-only management and arbitrary extension components remain unavailable. See the [retained differences](docs/pi-like-mac-verification.md#remaining-acceptance-and-differences).

## Development

`project.yml` defines the SwiftUI app targets and iOS app tests. The root `Package.swift` defines the host, client and integration tests; `Packages/PiRemoteCore` holds the shared protocol. Platform-specific process and network code stays outside that package. There is no TypeScript backend.

**Local debug tooling:** the Mac app has opt-in debug access for a repository Pi extension. Enabling it saves the choice across app restarts; Disable clears that choice. Each launch creates a fresh local capability. It provides bounded app state, rendered window-content PNGs and app-only semantic UI controls over a private Unix socket. UI controls can click supported ordinary controls, navigate, change appearance, open ordinary panels, append native draft text and scroll; they cannot submit prompts, run commands, control Pi/networking or change pairing. Captures and tool inputs can enter Pi history/model requests. Focused checks pass for the integrated controls. Native Sidebar and Pi commands clicks pass through the registered extension in a separately launched product-source check app with private storage. This does not verify attended consent, loaded-session native draft insertion, saved opt-in after relaunch or full UI acceptance. Earlier session-only builds require one new Enable confirmation in the rebuilt app. See [operation, privacy limits and evidence](docs/mac-debug-mode.md).

Verified unsigned build and test commands are in [native app verification](docs/native-apps.md#automated-checks). Compact-interface checks are recorded in [interface verification](docs/interface-verification.md). Personal signing and installation remain unverified; they are not current plan-completion requirements. The build settings use iOS 18 and macOS 15 as provisional floors, not tested supported versions. Pi 1.3.0 passes the recorded development checks; no broader supported-version range or complete terminal-parity claim is established.

Start with personal builds for iPhone 16 Pro and the current Mac. TestFlight comes later. A future phase can add accounts and a public connection service; its authentication, encryption and routing still require design.
